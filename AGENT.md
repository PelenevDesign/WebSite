# AGENT.md — как работать с этим проектом

Гайд для AI-агента / разработчика, вносящего правки в лендинг **PELENEV.DESIGN**.
Читай перед изменениями. Дизайн-система — в [DESIGN.md](DESIGN.md).

---

## 1. Что это

Двухстраничный лендинг на **ванильном стеке**: `HTML + CSS + JS`, без сборки и npm.
Внешние библиотеки — через CDN: **GSAP 3.12.5 + ScrollTrigger**, **Lenis 1.1.13**. Шрифт — **rsms.me/inter**.

Файлы:
```
index.html   — главная (hero, about, services, pricing, faq, footer)
work.html    — страница кейсов (заголовок + sticky-стек проектов + footer)
privacy.html — политика обработки ПД (152-ФЗ); статическая, без main.js и GSAP
styles.css   — все стили, токены в :root
main.js      — вся логика: Lenis + init-функции по секциям
assets/      — плейсхолдеры (svg/mp4), заменяет заказчик
DESIGN.md    — дизайн-система
```

Поверх статики работает PHP-CMS (описана в [ADMIN.md](ADMIN.md)):
```
config.php / db.php / api.php   — конфиг, PDO-слой, JSON-API админки
index.php / work.php            — обёртки: подставляют контент из БД в .html (см. .htaccess)
case.php                        — страница кейса из БД
cms-schema.js                   — единый список редактируемых полей (сайт + админка)
cms.js / portfolio.js           — применение контента и рендер кейсов на фронте
admin/                          — панель управления
install.php                     — разовая установка, УДАЛИТЬ с хостинга после запуска
```
Правило: новое редактируемое поле добавляется в `cms-schema.js` **и** в `cms-defaults.php`, иначе ключ мёртвый.

Админка v2 (`admin/`): сайдбар-разделы Дашборд/Заявки/Кейсы/Медиа/Контент/SEO/Интеграции; hash-роутер, тосты, поиск по разделу. Типы полей схемы: `text`, `image`, `href` (ставится на ВСЕ совпадения селектора), `attr` (произвольный атрибут, напр. `data-video`). Соцссылки в HTML помечены `data-cms="link-*"` — схема целится в них, а не в URL. Статусы кейсов: published/draft/hidden — публичные выборки фильтрует `projectRows()` в db.php (админка получает всё по признаку авторизации). Счётчики аналитики: ключи `integration-*` → `applyIntegrations()` вставляет код перед `</head>` на index/work/case. `gallery-tools.js` шлёт `status` при автосохранении галереи — не убирать, иначе черновик молча публикуется.

## 2. Запуск и превью

Статика, нужен любой http-сервер (не открывать через `file://` — сломается `fetch` видео-лоадера).
```
python3 -m http.server 4173   # → http://localhost:4173
```
Конфиг превью — `.claude/launch.json` (имя `site`, порт 4173).

**Верификация правок:** открой превью, проверь консоль на ошибки, прогони затронутую секцию скроллом/кликом. Скриншот-инструмент криво снимает проскролленные состояния — **сверяй геометрию/состояния через DOM-замеры** (`getBoundingClientRect`, computed styles), а не только глазами.

## 3. Критичные соглашения

### 3.1. Кэш-версии ассетов — ОБЯЗАТЕЛЬНО
Браузер агрессивно кэширует `styles.css` и `main.js`. После **любой** правки этих файлов подними версию в обоих HTML:
```
sed -i '' 's|styles.css?v=36|styles.css?v=37|; s|main.js?v=37|main.js?v=38|' index.html work.html
```
Иначе превью покажет старую версию. HTML не версионируется — для форс-релоада добавляй `?nc=<n>` к URL.

### 3.2. Правки в двух файлах
Шапка (`#topbar`), меню-оверлей (`#menu-overlay`), модалка формы (`#contact-modal` с `#chat`) и футер **дублируются** в `index.html` и `work.html`. Меняешь одно — меняй оба (различаются только href навигации: на work.html ссылки на секции главной ведут на `index.html#...`).

### 3.3. Lenis + якоря
Нативные `href="#section"` конфликтуют с Lenis. Для плавного скролла к секции используется `lenis.scrollTo(target, { force: true })` в обработчике кликов меню (`main.js`, блок «клик по ссылке меню»). Новые внутренние якоря должны идти через этот механизм.

### 3.4. scrollRestoration = manual
В `main.js` вверху стоит `history.scrollRestoration = 'manual'` + `scrollTo(0,0)`. Причина: при перезагрузке из середины страницы `once`-триггеры самоуничтожались во время начального `ScrollTrigger.refresh()` и роняли ScrollTrigger 3.12.5 (`undefined.pin`). Не убирать.

### 3.5. Guard'ы в init-функциях
`main.js` — один файл на обе страницы. Каждая `initX()` в начале проверяет наличие своей секции и тихо выходит, если её нет (например, `initPricing` не на work.html). **Добавляя новую init-функцию — ставь такой guard.**

## 4. Ключевые паттерны

- **Scroll-card** (наезд секций): для каждой светлой/тёмной секции —
  `gsap.fromTo(sec, {scale:.9}, {scale:1, scrollTrigger:{trigger:sec, start:'top bottom', end:'top top', scrub:true}})` на вход и обратный `1→.9` на выход (`immediateRender:false`).
- **Первая секция под hero** (`#about`) «выглядывает» из-под шапки: `margin-top:-110px`. Скролл-эффекты hero (параллакс гиганта/фона, скрытие контента hero) привязаны к `#about` — **если менять первую секцию, перепривязать триггеры в `initHero`**.
- **По-словный reveal:** `splitWords(el)` оборачивает слова и инлайн-иконки в `.wmask`/`.word`, потом анимируется `y:110%→0`. Используется для `.about__title`.
- **Видео-фоны** (`initVideos`): грузятся только на desktop (`min-width:769px`) и без reduced-motion; реагируют на ресайз окна; при отсутствии файла остаётся постер. Класс-маркер — `video[data-video]`.
- **Проекты** (`initProjects`, work.html): закреплённый `.projects-bg` кроссфейдит фото активного проекта; карточки `.pcard` «дышат» scale. Карточка намеренно не полноэкранная — `height: clamp(560px, 82svh, 900px)`, `width: min(96%, 1600px)`, чтобы по бокам оставался видеофон. **Важно:** `.ptexts` (`min(82%, 1200px)`) должен быть заметно уже карточки. Карточка «дышит» scale .9→1, и при уменьшенном масштабе её видимая ширина падает примерно на 10% — без запаса название кейса и плашка меты вылезают из-под неё по краям. Меняешь ширину одного — пересчитывай второе.
- **Галерея кейса** (`case.php`, инлайн CSS+JS): masonry на CSS-колонках (`.cg-grid`, `column-count` 3/2/1) — любое число фото из CMS-галереи, естественная высота, без искажений. Клик → кастомный fullscreen-попап `.cg-pop` с FLIP-ростом из карточки (invert→play на `transform`), затемнение+blur фона, счётчик, стрелки, закрытие (кнопка/ESC/клик-вне/обратный FLIP), навигация клавишами и свайпом/драгом через Pointer Events, предзагрузка соседних кадров, IntersectionObserver для появления карточек. Библиотек нет. Изображения не в HTML — грузятся из `/api.php?action=project`.
- **Видеофон всей страницы кейсов** (`initSiteBg`, work.html): `.sitebg` — `position: fixed` слой под всем контентом (`.workhero`, `#projects`, `.footer` имеют `z-index: 1`). Один rAF-цикл пишет `transform` + `opacity` на `.sitebg__layer`: появление (1.18→1.12 за 1.8 с), «плавание» на синусах, параллакс от курсора (lerp .055, ±10px), плюс дыхание виньетки. CSS-переходов на этом элементе быть не должно — подерутся с rAF. Цикл встаёт только на скрытой вкладке. Обрезка кадра держится на `inset: -44px`: логотип Kling начинается в 7.2% от низа исходника, запас проверен на 1440×560, 1440×900, 1024×1366 и 375×812.
  - **Не путать с `initWorkHero`** — это отдельная существующая функция, reveal заголовка `.workhero__word`. Имена функций в `main.js` глобальные: одинаковое имя молча перебивает соседа.
- **Табы категорий продублированы**: статичные в шапке (`.workhero .wtabs`) и в плавающем доке. Состояние между наборами синхронизирует `syncTabs` в `initDock` — обработчик на `document`, ставит `is-active` всем `.wtab` с нужным `data-cat`. `portfolio.js` вешает обработчики на **оба** набора (`tabGroups()`, защита от повторного навешивания — `group.dataset.bound`). Вкладки «Все» нет: по умолчанию активна первая категория, стартовый фильтр берётся из `activeCat()`.
- **Кнопка связи в доке** (`.dock__action`) открывает модалку прямо на странице. Блок `#contact-modal` с формой `#chat` **дублируется в `index.html` и `work.html`** (как шапка и футер) — правишь одно, правь оба. Любой триггер формы — это `href="#" data-contact`; переходов на `index.html#write` со страницы кейсов больше нет (обработчик хэша в `initContact` оставлен для внешних ссылок).
- **Док есть на обеих страницах**, разметка одна, поведение задаёт модификатор:
  - `work.html` — фильтр категорий (кнопки `.wtab` с `data-cat`, синхрон с табами в шапке);
  - `index.html` — `.dock--nav`: пункты меню ссылками (`data-section` для скролл-спая), клик идёт через `lenis.scrollTo`, активный пункт подсвечивается по текущей секции. «Кейсы» ведут на другую страницу и в спае не участвуют.
- **Плавающий док** (`initDock`): `.dock` (позиция + `--dock-fit`) → `.dock__shell` (единственный элемент, чей transform пишет rAF: видимость + магнит) → `.dock__inner` (стекло) → `.wtabs` с `.dock__pill`.
  - Появляется после `SHOW_AFTER = 260px` прокрутки и уходит, когда футер поднялся выше 75% экрана; переходы через lerp `.09` (~500 мс).
  - `--dock-fit` — коэффициент ужатия всего дока, если он шире экрана (`applyFit`). Гарантирует, что все категории видны без горизонтальной прокрутки: на 375px с пятью вкладками получается 0.67. Пересчитывается на resize, на изменение состава вкладок и после загрузки шрифтов.
  - **Сравнение с прошлой активной кнопкой в MutationObserver обязательно:** rAF каждый кадр дёргает класс `is-hovered`, и без проверки пересчёт пилюли читал бы `offsetWidth` каждый кадр.
  - Читаемость поверх видео: общий скрим `.sitebg__scrim` + стекло (`backdrop-filter`) на `.pcard`, `.ptexts__meta` и `.wtab`, тени у заголовков. Всё, что трогает общие с главной компоненты (футер), скоуплено через `body.page-work`.

## 5.2. Заявки с формы

`api.php?action=lead` (POST, публичный) принимает заявку: пишет её в таблицу `cms_leads` **до** отправки письма (чтобы не потерять при сбое почты), затем шлёт письмо на `config()['lead_email']` через `mail()`. Фронту отвечает успехом, если запись в базу прошла, — статус почты возвращается в поле `mailed`.

Защита: honeypot-поле `.cfield__trap` (заполнено → тихо игнорируем) и лимит 5 заявок в час с IP (`.htlead-attempts.json`, закрыт `.htaccess`).

На фронте отправка живёт в `submitChat` (`main.js`): `fetch` стартует параллельно с анимацией «отправляем», и если ответ не `ok` — вместо «Delivered» показывается ошибка со ссылкой на Telegram. Не делать вид, что заявка ушла, когда она не ушла.

## 5.3. Лид-магнит

`leadmagnet.css` + `leadmagnet.js` — самостоятельный модуль, подключён на `index.html`,
`work.html`, `case.php`, `journal.php`, `article.php`, `services/_template.php`.
Через 7 секунд показывает угловой виджет, по клику — сценарий из 4 шагов и форма.

**Через CMS не редактируется — так и задумано.** Тексты живут в `leadmagnet.js`,
отдельной вкладки в админке у него нет и быть не должно.

Заявка уходит в тот же `api.php?action=lead`. Обязательна **только почта**, имя и
описание проекта — по желанию. Бэкенд требует `name >= 2` и `message >= 2`,
поэтому за пустые поля фронт подставляет заглушки (`Без имени` и строку запроса) —
иначе заявка вернёт 422. Поле `company` не трогать: это honeypot, оно обязано
уходить пустым. Согласие с политикой — чекбокс, без него отправки нет (см. 5.1).

Квадратные 3D-иконки пунктов лежат в `assets/leadmagnet/` (`get-*.svg`,
`need-*.svg`) — заменяются подменой файлов, код трогать не нужно. Формат:
квадрат 400×400, скруглённая плашка `rx=96`, объект с бликом и тенью.

Слово «бесплатно» из текстов лид-магнита убрано намеренно — не возвращать.

**SEO-ограничения модуля (не откатывать).** Разметка виджета и модалки в DOM
заранее не кладётся: модалка добавляется в `openModal()`, иконкам `src`
проставляется оттуда же из `data-src`. Иначе поисковик видит на **каждой**
странице пять посторонних `<h2>` из сценария (на главной это было 5 заголовков
из 8) и семь лишних запросов за иконками. `leadmagnet.css` подключается
скриптом, а не `<link>` в `<head>` — как `<link>` он блокировал первый рендер
ради виджета, который всплывает лишь на седьмой секунде.

**Типографика.** `typo()` в `leadmagnet.js` проходит по текстовым узлам уже
собранной разметки и ставит неразрывные пробелы: после слов в 1–2 буквы (в
русском это почти всегда предлоги и союзы), после перечисленных в `GLUE3`
трёхбуквенных служебных слов, между числом и словом, перед тире. Руками
`&nbsp;` в текстах не ставить — правило работает само, в том числе на новых
строках. Склеивать любое трёхбуквенное слово нельзя: прилипнут «дом», «сад».

Переносы добивает CSS: `text-wrap: balance` на заголовках, кнопках и пунктах
списка (строки равной длины, без одинокого слова в конце), `text-wrap: pretty`
на абзацах. Длинные неразрывные куски в узкой модалке вредны — из-за них строка
уезжает целиком; поэтому в тексте согласия внутри ссылки стоит обычный пробел.

Переходы открываются через принудительный reflow (`void el.offsetWidth`), а не
через `requestAnimationFrame`: в неактивной вкладке кадр может не наступить, и
диалог остаётся с `opacity: 0`. Эта ошибка уже была — не возвращать rAF.

Повторный показ гасится через `sessionStorage['pd-leadmagnet']` (`closed` / `sent`).
На админке модуль не запускается (проверка `body.page-admin`).

Оверлей блокирует фон через `window.lenis.stop()` — инстанс Lenis специально
выставлен в глобалку в `main.js` и `service.js`. Одного `overflow: hidden` мало:
Lenis скроллит программно и его игнорирует.

## 7. Чего НЕ делать

- Не тащить сборщики/фреймворки/Tailwind — стек фиксированный.
- Не заливать крупные плоскости акцентом `#FF3C00` (только точечно).
- Не убирать `scrollRestoration = manual` и guard'ы init-функций.
- Не забывать про кэш-версии и дублирование шапки/футера на двух страницах.
- Не открывать сайт через `file://` при проверке видео.
