ФИНАЛЬНОЕ ОБНОВЛЕНИЕ — почините сначала это
============================================

Сайт сейчас работает неправильно, и по этой же причине проседает Яндекс.
Два действия закрывают почти всё. Делайте строго по порядку.


ШАГ 1. ЗАЛИТЬ ФАЙЛЫ ИЗ АРХИВА
------------------------------
Распакуйте и залейте в КОРЕНЬ сайта с сохранением папок.

Самое важное в архиве — db.php. Без него сейчас:
  • страницы кейсов отдают ошибку 500 (все 11 штук недоступны)
  • страница гайдов обрывается на середине — HTML не дописан,
    поэтому статьи не видны ни людям, ни поисковикам

Проверка после заливки:
    https://pelenevdesign.ru/case.php?id=7     -> должно открыться
    https://pelenevdesign.ru/journal.php       -> должны появиться статьи


ШАГ 2. ВКЛЮЧИТЬ .HTACCESS  <<< ГЛАВНАЯ ПРИЧИНА ПРОБЛЕМ С ЯНДЕКСОМ
------------------------------------------------------------------
На сервере лежит файл с именем htaccess-for-upload.htaccess.
Пока он не переименован в .htaccess, правила не работают.

Из-за этого 20 из 21 адреса в карте сайта отдают 404:

    /work        -> 404      (работает только /work.php)
    /journal     -> 404      (работает только /journal.php)
    /case/7      -> 404      (работает только /case.php?id=7)
    /sitemap.xml -> 404      (работает только /sitemap.php)

При этом каждая страница сообщает поисковику canonical именно на
несуществующий адрес, а robots.txt указывает на несуществующий
sitemap.xml. Яндекс строго слушается canonical: видит 404 и выкидывает
страницу из индекса. Google мягче — он нашёл /work.php по внутренним
ссылкам и оставил в выдаче. Отсюда и разница между поисковиками.

ЧТО СДЕЛАТЬ:
  1) переименуйте htaccess-for-upload.htaccess (из архива) в .htaccess
     и положите в корень сайта, рядом с index.php
  2) удалите с сервера старый htaccess-for-upload.htaccess —
     сейчас он ещё и открыто читается по прямой ссылке
  3) проверьте, все три адреса должны открыться:
        https://pelenevdesign.ru/work
        https://pelenevdesign.ru/journal
        https://pelenevdesign.ru/sitemap.xml

Если /work всё равно 404 — хостинг не читает .htaccess. Напишите в
поддержку: «включите AllowOverride All для моего сайта».

Что нового в этом .htaccess по сравнению с прежним:
  • одно зеркало: принудительно https и без www
  • /index.php и /index.html перекидывают на / (были дублями главной)
  • закрыты от скачивания .md, .sql, .zip, .log, .json

ШАГ 4. КАРТИНКИ — ОТДЕЛЬНАЯ БОЛЬШАЯ ПРОБЛЕМА
---------------------------------------------
Главная страница весит 37,9 МБ на компьютере и 12 МБ на телефоне.
Из них 25,5 МБ — это 14 скриншотов, залитых в формате PNG
(по 2–4 МБ каждый). В WebP они весили бы по 150–300 КБ.

Именно поэтому сайт «иногда не прогружается» на мобильном.

В этом обновлении:
  • фоновое видео (4,8 МБ) больше не грузится на телефонах,
    при экономии трафика и на медленной сети — минус 4,8 МБ сразу
  • новый api.php умеет сам делать webp и уменьшенные копии,
    но только для НОВЫХ загрузок

Уже загруженные 25 МБ нужно пережать отдельно — это меняет ссылки
в базе, поэтому делается скриптом с бэкапом. Скажите, когда будете
готовы, подготовлю.

ИКОНКА САЙТА (добавлено)
------------------------
В корень сайта кладутся два НОВЫХ файла:

    favicon.ico            (16/32/48, чёрный фон + белая P из логотипа)
    apple-touch-icon.png   (180x180, для iPhone и iPad)

И обновлённый assets/favicon.svg остаётся на месте.

Почему логотипа не было видно на телефоне: /favicon.ico и
/apple-touch-icon.png на сервере отдавали 404, а в разметке
apple-touch-icon указывал на assets/og-preview.jpg — это баннер
1200x630 для соцсетей, iOS обрезал его в квадрат.

Теперь на всех страницах подключены три варианта: ico для Яндекса и
старых браузеров, svg для современных, png для Apple.

После заливки иконка в уже открытых вкладках может не обновиться —
браузеры кешируют её отдельно и надолго. Проверяйте в новой вкладке
или после очистки кеша.
